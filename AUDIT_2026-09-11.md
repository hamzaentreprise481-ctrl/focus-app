## Bugs corrected

1. A local-only evaluation called `notFound()` during server rendering before its browser data loaded. The route now waits and reports missing local data honestly.
2. The form discarded competency-only results, and analysis rejected a competency unless a numeric score existed. Both now preserve explicitly entered levels independently of grades.
3. Deselected competencies and blank option values could remain in saved records. Saving now includes only selected, valid observations; legacy blank/deselected values are safely filtered on read.
4. Storage write errors were swallowed while success was displayed. Writes now return failure, preserve the form and do not report success. Corrupt reads preserve the original bytes and block overwrite.
5. Evaluation additions could not be completed/corrected. Creation and editing now share one editor; updating replaces the selected evaluation and its results without duplicating them.
6. No data was narrated as normal progression. An explicit insufficient-data case now prevents that claim. Competency-only evidence can still trigger existing evidence-based patterns.
7. Historical evaluation comparisons used scores from the future and other classes. They now use strictly earlier dates in the same class. Same-day ordering is deliberately not guessed.
8. Evolution labels counted intervals rather than observations. Labels now describe the actual two/three numeric evaluations involved.
9. Calendar dates could move one day backwards across timezones. Formatting fixes the timezone for date-only values.
10. Supabase logout failure could leave browser cookies while a success redirect was attempted. Local cookies, including chunks, are cleared in `finally`; a separate message identifies unconfirmed remote revocation.
11. Settings could attempt to render an object supplied as display metadata. Non-string display names now fall back safely.
12. The accompaniment dialog reported creation without persistence. It now presents read-only suggestions without a fabricated successful operation.

The grade-to-competency suggestion shortcut was removed. The existing classification thresholds and established example patterns are retained and tested. The profile explicitly separates observations from interpretation, and describes mastery percentages as synthetic indices rather than measured success rates.

## Architectural decisions and next work

No replacement application, repository, stack or provider was created. Work stays on the existing PR. Changes to analysis in this pass are correctness fixes expressly authorized by the full-product brief, not cosmetic threshold tuning.

The current user authorizes production deployment after a stable tranche passes its gates. Existing PR restrictions belonged to the earlier task. **Production is still blocked by missing provider access and real authentication/visual validation**, not by a request for another routine permission.

Before a real teacher pilot:

1. Restore the existing FOCUS Vercel/Supabase connector access. Inspect the actual schema and migration history, production/Preview env targets, teacher provisioning and deployment branch mapping.
2. Inspect/implement school membership, class assignment, enrollments, configurable periods, evaluations, per-student scores and explicit skill observations with foreign keys, server-side ownership and tested RLS. Write additive migrations only against the verified schema; use a transaction for an evaluation plus its results.
3. Replace demo fixtures/browser persistence with authorized server reads and writes. Test two teachers from different schools and ensure neither can read or alter the other's records.
4. Add configurable scales and periods, class creation/import, secure invitation/recovery, and actual observations/objectives/interventions before adding remote AI.
5. Verify the real login → class → partial evaluation → continuation → student competency history → logout workflow on desktop/tablet/mobile. Verify keyboard use, console, hydration, error states, refresh and recovery after provider failure.
6. Have a teacher time entry and follow-up over several sessions. Measure whether FOCUS saves more effort than it adds before believing the product's value proposition.

Remaining demo limitations: localStorage is neither encrypted nor multi-tenant persistence; simultaneous edits to the same evaluation can overwrite one another; changes to different evaluations in sequential tabs are merged and storage events reload the view. There is no automatic draft recovery on internal navigation. Shared-device local data cleanup and retention are unresolved; only fictitious records belong here.
